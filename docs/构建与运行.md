# 构建与运行

[文档首页](README.md) · [English](quickstart.en.md) · [环境与兼容性](compatibility.md)

以下命令均在仓库根目录执行。先选择需要的运行方式：

| 目标 | 入口 | 需要的环境 |
| --- | --- | --- |
| 理解控制流程 | 离线演示 | Python 3.10+ |
| 编译本地微基准、运行逻辑检查 | 基础构建 | Python 3.10+、Make、C 编译器 |
| 使用实际内核调度器 | 内核工具构建与加载 | 匹配的完整 Linux 源码、BPF 工具链及管理权限 |
| 复现数据库或工作流性能 | 对应实验协议 | 调度器、负载软件和相应 CPU/NUMA 配置 |

## 1. 体验离线控制流程

```bash
git clone https://github.com/Lss-lmj/kernadapt-industry-2026.git kernadapt
cd kernadapt
python3 demo/run_demo.py --out results/demo
```

该入口使用 Python 标准库和仓库代码，向策略检查器提供合成输入，展示有效配置、未知调度器、缺少恢复条件及角色权限等分支，并保存运行状态。无需编译 C 程序、加载调度器或调用模型 API。

成功时输出 `DEMO PASS`。主要文件为 `results/demo/summary.json`、`guard_*.json` 和 `runtime/` 下的状态记录。末尾的历史结果汇总读取已有实验记录，不代表本次演示测得的性能。[演示说明](../demo/README.md)

## 2. 构建基础工具

准备 Python 3.10+、Make 和 C 编译器，在 Linux 环境执行：

```bash
make build
```

构建脚本检查 Python 语法，并生成 `build/bin/owner_progress_bench` 与 `build/bin/flowbench` 两个 C 微基准。它不编译或加载 BPF 调度器。

需要检查控制面逻辑及现有数据时，可使用：

```bash
make test-all
make verify-results
```

`test-all` 包括控制面检查、FlowCausal 控制逻辑测试和历史数据核算。输出与含义见 [tests/README.md](../tests/README.md)。这些检查与重新测量调度器性能是不同步骤。

## 3. 构建内核调度器

准备与目标运行内核匹配的**专用 Linux 源码工作树**。该树需要包含 `tools/sched_ext` 和 `tools/lib/bpf`；仅安装 kernel headers 通常不够。

构建依赖包括 Clang/LLVM、C 编译器、Make、pkg-config、libelf、zlib、libbpf 和 bpftool，具体版本应与所选内核工具树匹配。运行内核需提供 sched_ext、BPF 和 BTF；参见[环境说明](compatibility.md)。归档实验包含 Linux 6.17 环境，其他版本应按接口逐项确认。

```bash
export KERNEL_SRC=/path/to/linux-6.17
./scripts/build-kernel.sh
export KERNADAPT_SCX_BIN_DIR="$KERNEL_SRC/tools/sched_ext/build/bin"
```

脚本会将项目调度器和接口头复制到该工作树的 `tools/sched_ext`，然后构建：

- `scx_simple`、`scx_lockboost`、`scx_locknest`、`scx_lockcoop`；
- LockCoop 用户态同步观测库 `liblockcoop_sync.so`；
- 基础 FlowCausal，以及 V2 的 `scx_flowcausal_v2`、`flowd_v2`、`flowevent_v2`。

该脚本只构建工具，不启动调度器。FlowCausal V2 也有独立构建入口：

```bash
make -C src/flowcausal/src KERNEL_SRC="$KERNEL_SRC" check-flowcausal-v2
```

ARM64 可在目标架构本机编译；跨架构构建需要配置相应工具链。`KERNEL_SRC`、`SCHED_EXT`、`SCX_BUILD` 和 `TARGET_ARCH` 的使用见 [FlowCausal Makefile](../src/flowcausal/src/Makefile)。

## 4. 加载与退出

在准备好的实验机器上，先查看参数：

```bash
"$KERNADAPT_SCX_BIN_DIR/scx_lockcoop" -h
sudo "$KERNADAPT_SCX_BIN_DIR/scx_lockcoop"
```

另开一个终端读取实际状态：

```bash
cat /sys/kernel/sched_ext/state
cat /sys/kernel/sched_ext/root/ops
```

结束时向当前 loader 发送 Ctrl-C，再检查 `state` 恢复为 `disabled`。加载期间的 CPU 范围、锁观测方式和参数必须与负载匹配；完整实验参数见对应报告。

## 5. 控制器与负载入口

```bash
python3 src/agent/run_kernadapt_online.py --help
python3 src/agent/run_mariadb_comparison.py --help
```

可选模型策略的 `LLM_MODEL`、`LLM_API_BASE` 等参数在 [llm_policy_agent.py](../src/agent/llm_policy_agent.py) 中定义。离线演示不需要这些参数。控制面运行状态默认写入根目录 `results/`。

数据库、锁微基准与工具工作流分别从以下入口开始：

```bash
python3 src/lockcoop/scripts/mariadb_oltp/formal_mariadb_oltp.py --help
python3 src/lockcoop/scripts/futex_mutex/run_mutex_monitor.py --help
python3 src/flowcausal/experiments/run_live_sandbox.py --help
python3 src/flowcausal/experiments/run_repo_ci_matrix.py --help
```

先按[结果与实验协议](benchmarks.md)确定需要复现的场景，再采用该场景的运行次数、CPU 范围、数据库准备和统计方式。接入自己的负载可参考[集成与测量](integration.md)。
