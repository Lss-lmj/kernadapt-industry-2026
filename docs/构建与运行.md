# 构建与运行

以下命令在项目根目录执行。路径变量应指向使用者本机目录。核心 Python 控制面直接从源码运行，不需要系统级安装。

## 1. 基础环境

已归档的 openEuler 主复测：24.03-LTS、aarch64、Linux 6.17.0-lockcoop-scx617、Python 3.11.6、GCC 12.3.1、Clang 17.0.6、Sysbench 1.0.20、MariaDB 10.6。完整环境见 `tests/lockcoop/records/arm_openeulerpaper53_node0all_no_nest_runs5_results_20260801.md`。

运行基础控制面需要 Python 3.10+、Make、C 编译器。Linux 发行版可使用包管理器安装 `python3`、`make`、`gcc`。

```bash
make build
make test-all
make demo
```

产物为 `build/bin/` 下的 C 微基准以及 `results/demo/` 下的 JSON、事件与 SQLite 状态。Python 语法检查不创建提交目录中的缓存。

## 2. 内核调度器构建

使用与目标机器匹配的完整 Linux 内核工作树，包含 `tools/sched_ext`、`tools/lib/bpf` 等源码。仅安装 kernel headers 通常不足以提供这些工具目录。内核至少需要启用 `CONFIG_SCHED_CLASS_EXT`、`CONFIG_BPF`、`CONFIG_BPF_SYSCALL`、`CONFIG_BPF_JIT` 和 `CONFIG_DEBUG_INFO_BTF`，具体要求按匹配版本的 Linux 文档检查。

准备 Clang/LLVM、GCC、Make、pkg-config、libelf、zlib、libbpf、bpftool 及构建该内核工具目录所需的依赖。以下脚本将项目调度器复制到**专用工作树**并构建；它不启动调度器。

```bash
export KERNEL_SRC=/path/to/linux-6.17
./scripts/build-kernel.sh
export KERNADAPT_SCX_BIN_DIR="$KERNEL_SRC/tools/sched_ext/build/bin"
```

脚本构建 `scx_simple`、`scx_lockboost`、`scx_locknest`、`scx_lockcoop` 、基础 `scx_flowcausal`，以及当前 V2 的 `scx_flowcausal_v2`、`flowd_v2`、`flowevent_v2`；同时构建 LockCoop 用户同步观测库。FlowCausal 的独立依赖变化原型保存在单独目录。ARM64 可在目标架构本机编译；跨编译需配置目标工具链。

FlowCausal 独立 Makefile 接受 `KERNEL_SRC`、`SCHED_EXT`、`SCX_BUILD` 和 `TARGET_ARCH`，示例：

```bash
make -C src/flowcausal/src KERNEL_SRC="$KERNEL_SRC" check-flowcausal-v2
```

## 3. 安装与真实运行

将 `KERNADAPT_SCX_BIN_DIR` 指向编译产物即可供控制平面查找，无需覆盖系统默认调度器。先查看 loader 参数，再在专用实验机执行加载：

```bash
"$KERNADAPT_SCX_BIN_DIR/scx_lockcoop" -h
sudo "$KERNADAPT_SCX_BIN_DIR/scx_lockcoop"
```

在另一终端检查 `/sys/kernel/sched_ext/state` 和 `/sys/kernel/sched_ext/root/ops`。结束时向当前 loader 发送 Ctrl-C，并检查 state 恢复为 `disabled`。微基准、数据库用户、数据目录和 CPU 亲和性参数见实验协议。

控制器帮助：

```bash
python3 src/agent/run_kernadapt_online.py --help
python3 src/agent/run_mariadb_comparison.py --help
```

可选模型策略使用 `LLM_MODEL`、`LLM_API_BASE` 等环境参数；API 凭据只保存在本地环境，具体变量与参数见 `src/agent/llm_policy_agent.py --help` 及该文件接口实现。离线演示不依赖外部模型。

## 4. 性能复现

归档主实验是 7 个调度器、64/128/192/256 线程、每点 5 轮、每轮 10 秒预热与 60 秒测量；每轮重启 MariaDB，固定 buffer pool，使用明确 NUMA 放置。实验参数与当轮调度器启动参数以对应报告为准。

```bash
python3 src/lockcoop/scripts/mariadb_oltp/formal_mariadb_oltp.py --help
python3 src/lockcoop/scripts/futex_mutex/run_mutex_monitor.py --help
python3 src/flowcausal/experiments/run_live_sandbox.py --help
python3 src/flowcausal/experiments/run_repo_ci_matrix.py --help
```

已有逐轮结果可使用以下命令重新汇总：`make verify-results`。完整复跑需要真实内核、数据库及相应硬件。
