# KernAdapt 项目简介

**KernAdapt：面向混合负载的自适应内核资源管控 Agent**

团队：OSKernel；学校：中国科学院大学；队长：孙健康；指导教师：郑晨。参赛方向为系统与技术创新。

## 背景与目标

数据库、代码工具与推理服务共享 CPU 时，资源利用率不能单独解释应用为何变慢：事务可能等待持锁线程，工具调用可能等待关键子进程。KernAdapt 将这些执行关系与服务目标联系起来，研究多核系统中的调度与资源配置。

## 技术方案

系统由用户态控制面与内核机制组成。KernAdapt 比较结构化配置，管理执行范围、记录、效果评价和恢复；LockCoop 通过 LockBoost 有界推进可信持锁者，以 LockNest 改善同锁后继的 CPU 放置；FlowCausal 根据实际工具返回依赖组织会话内调度，并核算会话 CPU 服务。

面向 OpenHarmony Linux 内核系统的接入设计涵盖产品与板级环境、内核接口、libc 同步语义、会话登记、访问权限和异常恢复。模块职责与具体文件位置见开发设计文档及仓库使用说明。

## 创新与结果

项目将锁交接前后的时间片调整与局部性放置结合，将工具返回依赖与会话服务结合，并使用配置选择与受限执行连接应用目标和内核机制。

256 线程 MariaDB OLTP 报告汇总中，相对 scx_simple，ARM64 节点 0、x86 全机稳定资源域和 RISC-V 全机实验的吞吐分别为 5.30、4.14 和 2.15 倍。KernAdapt 在 560 组配置选择实验中的平均 regret 为 0.04357；600 次独立决策中调整 147 次，其中 114 次正收益。FlowCausal 八工作流回放的平均完成时间降低 7.32%，全部完成时间增加 2.65%。

各结果保留平台、基线和批次；ARM64 与 x86 的报告汇总包含后续机制实验，详细数值与数据文件见仓库的实验结果说明。

## 材料与团队

项目提供工程源码、构建与演示脚本、开发设计文档、八章完整技术报告、57 页答辩 PPT/PDF、讲稿、专题报告及实验资料。OSKernel 团队的技术工作包括机制设计、系统实现、实验分析和工程文档；个人技术分工以实际贡献记录为准。
